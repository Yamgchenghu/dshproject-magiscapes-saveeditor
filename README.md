# <麦琪的花园> 民间存档修改器

Magi Scapes（麦琪的花园）的存档编辑器。C# / .NET 8 / WinForms，单文件 exe，双击即用。

不是官方工具，和开发商没有任何关系。用之前请先备份存档。

---

## 这是什么

直接读写游戏存档，不依赖游戏运行。所有改动都是**字节级外科手术**——只替换改动的字段，其余字节原样保留，然后修复外层所有长度链。不做整体重新序列化，所以不会因为「格式看着像」就把存档写坏。

游戏存档格式：UE5.3 `GVAS`（`++UE5+Release-5.3`），命名空间 `GenerativeGame`。

---

## 能改什么

### 玩家
- 角色名（同时改存档列表里显示的名字）
- 生命 / 生命上限、魔力、饥饿、体温 / 上限、毒素 / 上限
- 一键回满
- 声望经验（声望等级由游戏按经验重算，所以只开放经验）

### 小队
- **编号 + 下拉框**的行式编辑，直接选人换人
- 上下调序、移出、新增
- **突破 3 人上限**：游戏自带界面只给 3 个位置，但存档里小队就是个名单数组，没有专门的人数字段。**4 人已在游戏内实测通过**——第 4 个人正常跟随，对话菜单里有「离开小队」，存读档都不掉。更高人数（6、10、40…）用的是同样的字节结构，理论上一样，但没人实测过，界面里给了上限输入框自己填。

### 背包
- 数量（全部堆满 / 单个改）
- 按名称或 ID 添加物品
- 物品详情：名称、描述、属性、词条等级与稀有度

> **官方道具和 AI 道具不是一回事**，这一点很重要，见下面「两个必须知道的坑」。

### NPC
- 名字、背包物品数量、背包增删
- 战斗属性：攻击力、魔力攻击力、暴击率、暴击伤害、闪避率、最大生命、最大魔力、攻击速度、移动速度、移动加速度
- 记忆：Type + Priority（Parameters 只读，改了游戏也不认）
- 招募 / 驱逐

### 营地
- 营地名、等级、升级日
- **位置**（含整块领地的格子一起搬，游戏才认）
- 三个名单：营地 NPC / 已招募 / 已驱逐

### 世界
- 世界时间（小时数）
- 传送石激活状态

### 地图
- 分区块可视化编辑地形
- 全部 11 层数据（默认只显示有意义的层，可开「显示全部层」）
- 营地范围框选、「整块显示」看完整区块
- 放置物：查看、旋转、删除
- 箱子物品数量

### 资料库
- 物品名 / NPC 名与 ID 的对照表，读到就自动补全
- 支持导出 / 导入（自定义加密格式，见下）

## 两个必须知道的坑

### 一、官方道具只能改数量

| | 官方道具（7 位 ID） | AI 道具（8 位以上 ID） |
|---|---|---|
| 定义在哪 | 游戏数据表 `DT_Items` | **存档本身** |
| 存档里那份是什么 | 缓存副本 | 唯一权威 |
| 改名称/描述/属性/词条 | 被游戏覆盖，**可能坏档** | **正常生效** |
| 能改什么 | **只有数量** | 全部 |

官方道具的 `ItemConfig` 只是数据表一行的缓存。游戏读档时会用数据表重建它，所以改了文字会被覆盖；格式对不上还可能让存档读不进去。编辑器在这件事上做了两道闸：`ItemDetailView.CanEditContent` 挡住所有写入方法，UI 再按同一标志选对话框。官方道具点开只有数量能输入，其余字段只读显示。

AI 道具（`100000xx` / `200000xx`）的完整定义就在存档里，游戏原样读取，所以随便改。

### 二、带等级曲线的属性改了不生效

`EquipmentAttributeMap` 里混着两种值：

- **扁平值**（暴击率 30%、攻击范围 0.69）→ 改了就生效
- **曲线值**（攻击力，`RowName=3010046_PhysicalDamage`）→ `Value` 只是倍率，真实数字按等级从曲线算

存档里攻击力写着 `Value=1`，游戏里显示 **99**。以前编辑器照样让你改，读档被重算覆盖，看起来就是「改了不生效」。

现在这类属性显示为灰色并注明曲线行，要提升只能改**词条等级**。

### 还有：数量别超上限

游戏读档时会把 `Count` 夹回 `MaxStack`，看起来像被回退。两个物品对话框都会拒绝超上限的输入并告诉你上限是多少。

## 资料库

`%LOCALAPPDATA%\GenerativeSaveEditor\catalog.json`，只存**名称 + ID**，不存别的。

收录规则（按用户要求）：

- 官方物品 ID 是 7 位；8 位以上是 AI 生成，不收
- 官方 NPC 的 ID 里带小写字母；玩家招募的是 6 位全大写 + 数字，不收（背包仍可编辑，遣散后只能靠 ID 招回）
- **箱子物品和地图放置物不收**——它们没有 `ItemConfig`，压根没有名字数据
- 名字等于 ID 的行没有意义，会被丢掉

每次打开存档自动补全。

### 导出 / 导入格式

自己定的加密格式，避免直接看到明文：

```
JSON → UTF-8 字节 → Base64 → 每个 Base64 字符转 2 位十六进制 → 
这些十六进制字符的 UTF-8 字节 → 比特流（MSB 优先）→ 1~2 位叠数计量法
```

叠数计量法规则：

- 1~9 个连续相同位：一位数字
- 10~549 个：一个字母 + 一位数字（`A`..`Z` = 10..260，`a`..`z` = 270..520，`%` = 530，`@` = 540）
- 超过 549：`@9` + `0` + 余数，那个 `0` 是截断标记
- 比特流默认以 `1` 开头；要表示真正的前导 0，就在开头补一个字面 `0`
- 例：`@903` = 552 个连续 1；`0@903` = 552 个连续 0；`@93` = 549 个 1 + 3 个 0

## 存档位置

```
%LOCALAPPDATA%\GenerativeGame\Saved\SaveGames\Steam_<你的SteamID>\GameSave_1\
├─ Manifest.sav
├─ Primary\Modules\     146 个 .sav
└─ Versions\v_<id>\     游戏自己的快照
```

编辑器只改 `Primary\Modules\`，同时把改过的模块同步进 `Versions\v_*\` 里的同名文件——否则游戏从快照恢复时会把改动盖掉，看起来就像「改了又变回去了」。

**改之前请关掉游戏。** 游戏退出时会把内存状态整体写盘，覆盖你的修改。编辑器检测到游戏在跑会提示。

## 编译

需要 .NET 8 SDK 或更高。

```bash
dotnet build MagiScapes.SaveEditor.sln -c Release
```

单文件发布：

```bash
dotnet publish src/GenerativeSave.Editor/GenerativeSave.Editor.csproj \
  -c Release -r win-x64 --self-contained true \
  -p:PublishSingleFile=true \
  -p:IncludeNativeLibrariesForSelfExtract=true \
  -p:EnableCompressionInSingleFile=true \
  -o publish
```

产物约 63 MB（自带运行时，目标机器不用装 .NET）。

## 一些实现细节

**为什么是字节级修改而不是重新序列化。** 存档里同一段字节可能被多个结构引用，整体重写很容易在某个不起眼的字段上写错一个长度。改哪个字段就只换哪个字段的字节，然后从内到外修一遍所有外层长度，出问题的面小得多。

**`Parse()` 不是幂等的。** 每次调用都重建整棵属性树，之前拿到的 `SaveProperty` 引用全部变成孤儿，上面挂的待写入值会静默丢失。所以只在没解析过的时候解析。

**读值要读暂存值。** `MarkDirty` 只是记下「待写入」，`Value` 仍然是磁盘上那份。写完立刻读 `Value` 会读到旧数据，看起来像写入失败。`ReadIds` 之类的地方优先读 `PendingValue`。

**地图层 9 和 10 不是编辑记录。** 那两层的意思是「这个格子被加载/保存过」，所以几乎每个格子都有。默认不显示，需要时开「显示全部层」。

**营地的格子表里 `CellIndex` 和 `DetailIndex` 是 -1。** 只有 `DetailX`/`DetailY` 带真实数据。所以搬营地时只能动这两个，动了别的游戏就不认。
